# TPL-007 inputs: beta factors and substation fields

NERC TPL-007 makes a GMD Vulnerability Assessment mandatory for most
transmission planners, and sets the field they plan against as

```
E_peak = 8 x alpha x beta   (V/km, benchmark GMD event)
```

`alpha` is fixed by geomagnetic latitude. `beta` is where the geophysics
lives, and the standard offers two routes to it: look it up from a table of
1-D physiographic regions, or compute it from a "technically justified"
Earth model. This page walks the second route, and then hands the result to
whatever power-system tool does the network solve.

The two functions here are deliberately at the **boundary** of bezpy's
scope. Reactive power loss, harmonics, transformer thermal response, and AC
load flow are not implemented and will not be — see
[Network GIC](network-gic.md). What bezpy can do that a power-flow tool
cannot is produce a defensible, site-specific geoelectric field. These
functions put that field into the units and at the locations the power-flow
tool is expecting.

## Why bother, when there is a table?

The tabulated `beta` is a 1-D layered Earth averaged over a whole
physiographic region. Real conductivity is 3-D and varies sharply over
distances much shorter than a region. So the table can be conservative or
optimistic by a large factor at any particular substation, and it gives no
way to tell which.

That is the entire case for doing this: a utility choosing whether to spend
on transformer mitigation is making that decision on a number that may be
off by a factor of two, in an unknown direction.

```python
import bezpy
from bezpy.tpl007 import beta_factor, tabulated_beta, alpha_factor, peak_geoelectric_field

tabulated_beta("AP1")        # 0.33 -- the Appalachian region average
```

## Computing beta from measured impedances

`beta` is defined against the reference geomagnetic field waveform NERC
distributes with TPL-007 (the March 13–14 1989 Ottawa record scaled to 60°
geomagnetic latitude, 10 s sampling). bezpy does not redistribute it — you
supply it:

```python
import numpy as np

# The two columns of NERC's benchmark waveform file, in nT.
mag_x, mag_y = np.loadtxt("benchmark_waveform.txt", unpack=True)

sites = bezpy.data.load_mt_sites(bbox=(-84, 36, -76, 42), min_rating=3)
betas = beta_factor(sites, mag_x, mag_y, dt=10)
print(betas)
```

```
                latitude  longitude  peak_E   beta  beta_x  beta_y  reference_peak_E
site
VAQ58              38.44     -78.12   5.912  0.739   0.701   0.402             8.000
VAQ59              38.71     -77.85   2.031  0.254   0.244   0.131             8.000
...
```

Every row carries `reference_peak_E`, the denominator it was normalized by,
so an exported table stands on its own in a filing.

!!! warning "The calibration check"
    The reference waveform is scaled precisely so the reference Quebec Earth
    model yields 8 V/km. `beta_factor` computes that number from *your*
    waveform and reports it. If `reference_peak_E` comes back as 8.0, you
    supplied the right file. If it does not, `beta_factor` warns — and the
    `beta` values, while still a correct ratio of peak fields, are not the
    standard's `beta`. A literal `E / 8` would have silently absorbed that
    error.

Compare against what the table would have given you — this is the number
that motivates the whole exercise:

```python
betas["tabulated"] = tabulated_beta("AP1")
betas["ratio"] = betas["beta"] / betas["tabulated"]
```

Then the planned-against field, per site:

```python
alpha = alpha_factor(52.0)                        # geomagnetic latitude, degrees
betas["E_peak"] = peak_geoelectric_field(alpha, betas["beta"])   # V/km
```

!!! note "alpha has two definitions and they disagree"
    Equation 3 and Table 2 differ by up to 0.026 (at 45° the formula gives
    0.177 against a tabulated 0.2). Both are permitted; `alpha_factor`
    defaults to the formula and takes `method="table"` for the other. State
    which you used.

Read [validation item 1.3](../validation.md) before putting `beta_factor`
output in a filing. The implementation reproduces the standard's own Table 3
to within about 0.1 in `beta` when driven with a synthetic storm, with a
residual systematic low bias that is expected to vanish once the real
reference waveform is used — but that has not yet been demonstrated.

## Geoelectric fields at substation locations

MT sites are wherever the surveys happened. A planner needs E where their
substations are. `calc_substation_fields` maps one onto the other using the
same gnomonic Delaunay interpolation the line-voltage kernels use, so a
substation field and a line voltage from the same run are consistent to
rounding error.

Substation coordinates are also, usefully, far less sensitive than full
network topology — a utility can share a list of latitudes and longitudes
much more readily than a bus/branch model.

```python
import pandas as pd

subs = pd.read_csv("substations.csv")            # code, latitude, longitude
latlons = subs[["latitude", "longitude"]].values

e = bezpy.calc_geoelectric_field(b_obs, sites, interp="secs",
                                 window=("2024-05-10", "2024-05-12"))
e_sub = bezpy.calc_substation_fields(e, latlons, names=subs["code"])

e_sub["Ex"]        # (time, substation), mV/km
```

Extrapolation is refused rather than guessed. A substation outside the
convex hull of the MT network comes back NaN and is flagged:

```python
outside = e_sub["substation"][~e_sub["within_hull"]].values
if len(outside):
    print(f"no MT coverage for: {list(outside)}")
```

The peak per substation is the handoff artifact:

```python
magnitude = np.hypot(e_sub["Ex"], e_sub["Ey"])
peaks = pd.DataFrame({
    "latitude": e_sub["latitude"],
    "longitude": e_sub["longitude"],
    "E_peak_mV_km": magnitude.max("time"),
    "E_peak_time": magnitude.idxmax("time"),
}, index=e_sub["substation"])
peaks.to_csv("substation_peaks.csv")
```

## Where this stops

`substation_peaks.csv` and the `beta` table are inputs to a GIC network
solve, not the answer. From here the numbers go into whatever tool holds the
network model — PowerWorld, PSS/E, or `bezpy.tl.network.Network` if you have
the DC-equivalent topology and only need transformer neutral currents (see
[Network GIC](network-gic.md)).

The reason to hand off rather than continue is not effort, it is
verifiability: real network models are not public, so nothing downstream of
this point could be validated in the open. Everything up to it can be, and
is — [validation item 1.3](../validation.md).
